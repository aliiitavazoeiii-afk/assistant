# Setup

## 1. Central backend — can be installed before OpenAI is funded

Requirements: Linux, Node.js 22+, systemd.

From repository root:

```bash
sudo bash server/install.sh
curl http://127.0.0.1:8787/health
```

The installer generates a random `ASSISTANT_APP_TOKEN`, creates private runtime configs/state and starts `assistant.service`.

`OPENAI_API_KEY` may stay empty. The service remains healthy, but `/v1/agent/*` returns `503 OPENAI_API_KEY is not configured yet` until the key is added.

When ready:

```bash
sudo nano server/.env
```

Set:

```env
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5.6-luna
OPENAI_REASONING_EFFORT=low
```

Then:

```bash
sudo systemctl restart assistant
curl http://127.0.0.1:8787/health
```

The backend binds to localhost by default. Put it behind HTTPS/Caddy or a private VPN for a physical phone.

## 2. Android

Open the repository in Android Studio and install the `app` module (`minSdk 29`, `targetSdk 35`).

In the app set:

- **Server URL** — HTTPS URL for the central backend (emulator default remains `http://10.0.2.2:8787`)
- **App connection token** — the `ASSISTANT_APP_TOKEN` generated by `server/install.sh`

The app token is stored using Android Keystore in v0.2. The OpenAI API key must never be entered into Android.

Grant only the Android permissions/features you want: microphone, camera, contacts/call/SMS, location, notifications, media, exact alarm and optional Notification Access/Wake Word.

Calls and SMS require an explicit local confirmation dialog before execution.

## 3. Optional Linux/VPN monitoring nodes

On each server you want Assistant to read:

```bash
sudo bash node-agent/install.sh
curl http://127.0.0.1:9443/health
```

The installer prints a unique `AGENT_SECRET`. Register that node and secret on the central backend as described in `OPS_CONTROL_PLANE.md`.

The node is read-only: health, allowlisted service status/logs, and VPN-expiry adapter queries. It has no remote shell/write endpoint.

## 4. VPN expiry workflow

The bundled `vpn_json.py` adapter reads `/etc/assistant-node/vpn-users.json`. Use it for testing, or replace the configured adapter with a panel-specific adapter that emits the same JSON contract.

A disabled `daily-vpn-expiry` automation is seeded in `server/data/automations.json`. Configure node IDs and messaging provider first; only then enable it. Outbound messaging additionally requires `ASSISTANT_ALLOW_MESSAGES=true`.

## 5. Business systems

Configure named endpoints in private `server/config/integrations.json`. This is the extension point for Darma, expense tracker, CRM, VPN panel APIs, deployment gateways and other internal systems. Only explicitly registered operations are callable.
